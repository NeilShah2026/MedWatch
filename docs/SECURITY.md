# Security and privacy controls

MedWatch handles protected health information (PHI). This document lists each control, where it
lives, and what must happen before real patients use the system. **The demo build uses synthetic
data only and is not for clinical use.**

## Known limitations

- The CSP allows any `*.supabase.co` project for `connect-src` because `vercel.json` is static; pin it to the production project URL.
- `pg_net` triggers and cron jobs need `npm run secrets:sync` to have stored the function URL and `CRON_SECRET` in Vault; until then on-demand runs come only from the web app, and nothing is scheduled.
- SMS messages are deliberately content-free; delivery receipts are recorded as `sent`/`failed` only.
- Audit `changes` record column names, not old/new values. If your compliance team needs value-level history, add an encrypted history table rather than widening `audit_log`.
- React Router v6 (required by the spec) has open advisories in the `@remix-run/router` range; review before production or upgrade when the spec allows.

## Before production (must be done by humans)

1. **Separate production Supabase project** on a plan with a signed **BAA** and the **HIPAA add-on**; enable point-in-time recovery and backups; restrict dashboard access.
2. **BAA with the AI gateway and model provider**, or keep `AI_ENABLED=false`.
3. **BAA with the SMS vendor**, or keep `SMS_PROVIDER=console`.
4. Confirm Vercel's terms; no Vercel functions may touch patient data (none exist).
5. **Attorney review** of the privacy policy, terms of use and consent documents (all marked DRAFT).
6. **Clinician sign-off** on every rule file and the check-in prompt (`supabase/functions/_shared/prompts/checkin_v1.ts`).
7. Set `mfa_required = true` for all staff; remove demo accounts; never run the seed in production.
8. **Penetration test** and an independent security review (RLS policies, functions, CSP).
9. Incident response plan, access reviews, and log retention policy.
10. Pin the CSP `connect-src` to the production project and set `VITE_APP_ENV=production` (removes the demo banner).
